Now that we can determine our repository is up-to-date and the configuration is set-up, we can create our first QC issues. Selecting the _Create_ tab 
will open a page that allows you to either _Select_ a Milestone and add more files to it, or create a _New_ milestone. Since this project does not have any
existing milestones, we will select the _New_.

<div style="display: flex; justify-content: center;">
  <img src={createMilestone.src} style="width: 75%;" />
</div>

When creating a new milestone, you must provide a milestone name and have the option to include a description of this milestone. Additionally, on this page is
the opportunity to add files to be QCed. Clicking on the _Create New QC_ button will open a modal pop-up with 4 tabs:

<Steps>
    1. **Select a File**

        The first tab contains a file tree to select the file to be QCed. Since issues and files are one-to-one, you _must_ select one and only one file.
        <div style="display: flex; justify-content: center;">
            <img src={createFileSelect.src} style="width: 75%;" />
        </div>

    2. **Select a Checklist**

        The second tab requires you to select a checklist for which the file must be reviewed against. These are templates that can be edited directly in the
        tab before creating the QC.
        <div style="display: flex; justify-content: center;">
            <img src={createChecklistSelect.src} style="width: 75%;" />
        </div>

    3. **Select Relevant Files**

        In `ghqc`, we recognize a file hardly ever stands alone in an analysis. A file sources outputs from another, uses helper functions, or expands on a previously
        QCed file. Because of this, we can add files which are relevant to the current QC, while adding some rules how a QC must be approved. 
        
        Relevant files have 4 classifications:
            * Previous QC - A QC which has previously been done for this file (or a very similar one). Must be approved before the main issue can be.
            * Gating QC - A QC of a file which the main file depends on. The gating QC must be approved before the main issue can be.
            * Relevant QC - A QC of a file which is relevant to the current QC, but does not directly change the current QC. Has no baring on the main QC's approval.
            * Relevant File - A file which is relevant to the current QC, but does not require QC. Has no baring on the main QC's approval.
        For more details, reference the [Relevant Files section](../create/#relevant-files).

        To add a relevant file, select the _Add Relevant File_ button. This will open a pop-up with a file tree. Any files that have issues created for them will have 
        their issue number next to the file as well. 

        <div style="display: flex; justify-content: center;">
            <img src={createRelFileSelect.src} style="width: 75%;" />
        </div>
        <div style="display: flex; justify-content: center;">
            <img src={createRelFilePopUp.src} style="width: 75%;" />
        </div>

    4. **Assign Reviewer**

        Optionally, you can add reviewer(s) to the QC in the tab. If you do not know who will be reviewing your QC at the time of initialization, the reviewer can add 
        themselves to the GitHub Issue and `ghqc` will treat it the exact same.

        <div style="display: flex; justify-content: center;">
            <img src={createReviewSelect.src} style="width: 75%;" />
        </div>
</Steps>

After the file and checklist is selected, you can queue the QC for creation. This allows you to assign multiple files for QC and edit them as needed before creation.

<div style="display: flex; justify-content: center;">
    <img src={createQueued.src} style="width: 75%;" />
</div>

After all files files you wish to create together are queued, select the "Create QC Issues" button. This will create the milestone and issues and return a pop-up with links
to the create issues.
