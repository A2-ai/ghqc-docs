## Approved Issue Thread

Approval of a QC Issue is fairly straightforward, it leaves metadata within the issue for when the file was approved so that future users can reference the version
of the script that was approved. Therefore, on this page we'll spend some time reviewing the final issue thread with all of the comments.

In the below example, we can notice a few key aspects:

* The QCer was assigned as the **Assignee**, whether in the [Assign app](../assign) or [self-assigned](../review/#set-assignee)
* The QCer chose to [push their comments](../review/#push-qc-comments) in-line and use the [Notify app](../notify)
* The Author made the edits requested by the QCer and notified the changes using the [Notify app](../notify)
* Once the QCer was satisfied with the changes, they approved the issue.

## Close Milestones

When all Issues within a Milestone are closed, you may [close the Milestone](https://docs.github.com/en/issues/using-labels-and-milestones-to-track-work/creating-and-editing-milestones-for-issues-and-pull-requests).

This communicates to the other `ghqc` apps that the Milestone is completed.
