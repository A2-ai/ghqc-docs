`ghqc configuration status` prints a focused configuration report for the currently resolved config directory.
It is the CLI counterpart to the UI's [Configuration](../../../features/configuration) tab and a narrower alternative to `ghqc sitrep`.

```bash
ghqc configuration status
```

## What It Checks

Status loads configuration from the resolved directory and reports:

- the resolved local configuration directory
- Git repository owner/repo when the directory is a Git clone
- git status details, including dirty files when present
- the configured checklist directory and the number of loaded checklists
- whether the configured logo file exists
- the prepended checklist note, when one is configured
- a checklist-by-checklist item count summary

Status does not dump the full resolved `options.yaml` values.
Option values that do surface here do so indirectly — the checklist display name in the section headings, the checklist directory in the summary line, and the logo path in the logo line.
For a complete view of the resolved options, use the UI's [Configuration](../../../features/configuration) tab or `ghqc sitrep`.

## Non-interactive

`ghqc configuration status` does not have an interactive mode.
Run it directly, or add `--config-dir` to inspect a specific configuration directory.

```bash
ghqc configuration status
```

```bash
ghqc configuration status --config-dir /path/to/config
```

### Options

| Flag | Description |
|---|---|
| `--config-dir` | Override the configuration directory to inspect. |

### Validation and Defaults

- Status uses the same configuration-directory resolution order as the rest of `ghqc`
- If `options.yaml` is missing or cannot be parsed, `ghqc` falls back to built-in defaults instead of aborting
- The built-in `Custom` checklist is always present, even if the configured checklist directory is missing
- If the directory is not a Git repository, status still prints configuration details but omits Git repo metadata
- If a custom `logo_path` is configured but the file is missing, status prints a warning
- If `logo_path` is left at its default `logo.png` and the file is absent, no warning is printed
- A configured `checklist_display_name` is title-cased in the report headings, so a custom name such as `review checklist` prints as `Review Checklist`
- Status is read-only: it never fetches from or writes to the configuration repository, so a `behind` state it reports stays until you run [`ghqc configuration update`](./update)

## Example

```text
== Directory Information ==
📁 directory: /Users/you/.local/share/ghqc/ghqc-config.git
📦 git repository: org/ghqc-config
Repository is up to date!
📋 Checklists available in 'checklists': 4
✅ Logo found at logo.png

== Checklists Summary ==
📌 checklist note:
│  Note: edit checklist items as needed

- Code Review: 10 checklist items
- Custom: 1 checklist items
- General Script: 3 checklist items
- Report: 7 checklist items
```

When the clone has fallen behind its remote, or has local edits, those appear on the git repository lines.

```text
== Directory Information ==
📁 directory: /Users/you/.local/share/ghqc/ghqc-config.git
📦 git repository: org/ghqc-config
Repository is behind by 3 commits
⚠️ 1 files with uncommitted changes:
  - options.yaml
📋 Checklists available in 'checklists': 4
```
